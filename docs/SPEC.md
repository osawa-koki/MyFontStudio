# 手書きフォント作成サイト 仕様書

最終更新: 2026-11-08

## 1. 概要・目的

自分の手書き文字から、PCにインストールしてWordなどで使えるフォントファイル（.ttf / .otf）を生成するWebサイトを作る。主な用途は履歴書などの書類を手書き風の文字で作成すること。

**前提**

- すべての処理をブラウザ内で完結させる。サーバー、アカウント、外部送信は一切なし（静的サイト）
- ユーザーは文字列を入力し、1文字ずつCanvasに手書きして登録していく
- 作業内容はzipで保存・再読み込みできる。zipにはフォントファイルと手書きの生データ（ベクター＋プレビュー画像）を含める
- 生成したフォントをその場で適用して確認できる画面を用意する

**用語**

| 用語 | 意味 |
| --- | --- |
| グリフ | 1文字分の字形データ |
| ストローク | ペンを置いてから離すまでの1本の線（座標と筆圧の列） |
| em | フォントの基準座標空間。本アプリでは1000×1000単位 |
| プロジェクト | 1つのフォントを作るための作業データ一式（フォント名、設定、全グリフ） |

## 2. 技術スタックとディレクトリ構成

Vite + React + TypeScriptの静的SPAとして実装する。ビルド成果物は任意の静的ホスティング（Vercel / Netlify / GitHub Pages等）に置けること。

## 3. 画面構成とルーティング

3画面構成とし、共通ヘッダーからいつでも移動・保存・読込ができるようにする。

| パス | 画面 | 内容 |
| --- | --- | --- |
| `/` | 使い方 | アプリの説明、手順、インストール方法。「はじめる」「zipを開く」ボタン |
| `/editor` | 入力ページ | 文字列入力、文字一覧、手書きCanvas、グリフ登録 |
| `/preview` | 適用画面 | textareaの入力を生成フォントで表示、.ttf / .otfダウンロード |

**共通ヘッダー**

- 左：アプリ名、ナビ（使い方 / 入力 / プレビュー）
- 中央：フォント名（クリックで編集）、登録済み文字数
- 右：「zipで保存」「zipを開く」「フォントをダウンロード」（.ttf / .otfを選べるドロップダウン。既定は.ttf）
- 未保存の変更がある場合は「未保存」バッジを出し、タブを閉じる際に `beforeunload` で警告する

**状態の共有**

プロジェクト状態はzustandストアで保持し、画面遷移しても失われないようにする。ストアが変わるたびにIndexedDBへ自動保存する（500msデバウンス）。起動時に自動保存データがあれば「前回の作業を復元しますか？」と確認する。

**レイアウト**

PC（幅1280px以上）とタブレット（iPad等、幅768px以上）を主対象とする。スマートフォンでは崩れない程度に縦積みで表示すればよい。

## 4. 入力ページ（/editor）

文字列を入力すると未作成の文字が順にCanvasに展開され、描いて「保存」を押すとその文字のグリフが登録され、次の文字へ進む。

### 4.1 画面構成（上から順に）

1. **文字列入力欄**：テキスト入力＋「追加」ボタン（Enterでも追加）
2. **プリセット追加**：「ひらがな」「カタカナ」「数字」「英字」「記号」のボタン。押すとその文字群を一覧に追加
3. **文字一覧（CharQueue）**：追加した文字をチップで横並び表示。作成済みはサムネイル付きで緑、未作成はグレー、編集中は枠線で強調。クリックでその文字の編集に移る。「未作成のみ表示」フィルタ付き
4. **編集中の文字**：大きく表示し、コードポイント（U+3042）も添える
5. **手書きCanvas**（正方形、表示サイズは画面に合わせて360〜560px）
6. **操作ボタン**：元に戻す / やり直し / クリア / 前へ / スキップ / **保存**
7. **ペン設定**：太さ（スライダー）、筆圧の有無、お手本表示のON/OFF

### 4.2 文字列の取り込みルール

- 入力文字列は `Array.from()` でコードポイント単位に分割する（サロゲートペア対応）
- 重複は除外し、入力順を維持して一覧の末尾に追加する
- 空白・改行・制御文字は除外する（半角スペースと全角スペースはフォント生成時に自動で含める）
- NFC正規化をかけてから取り込む
- 絵文字や結合文字（異体字セレクタ付きなど）は対象外とし、取り込み時に「対応していない文字」として通知する

### 4.3 Canvasの仕様

- 内部座標は0〜1000の正方形（em座標）に正規化して記録する。表示サイズが変わってもデータは不変
- `devicePixelRatio` を考慮して高解像度で描画する
- **ガイド線**：外枠、十字の中心線（破線）、ベースライン（y=880）、推奨描画範囲（内側余白50を示す枠）。半角文字のときは英字用のガイド（x-height、キャップハイト）も表示する
- **お手本**：編集中の文字を既存フォント（sans-serif）で薄いグレーで背景に表示する。ON/OFF切り替え可。お手本はグリフデータには含めない
- **入力**：Pointer Eventsで扱い、マウス・タッチ・ペン（Apple Pencil等）に対応。`touch-action: none` でスクロールを抑止。ペン使用時はパームリジェクションとしてtouch入力を無視する
- 筆圧は `PointerEvent.pressure` を使う。マウスなど筆圧が取れない場合は速度から筆圧を推定する（perfect-freehandの `simulatePressure`）
- 描画中の表示は、保存後のフォントと同じ輪郭化処理（第5章）で描く。見たままの形がフォントになるようにする

### 4.4 操作の挙動

| 操作 | 挙動 | ショートカット |
| --- | --- | --- |
| 元に戻す / やり直し | ストローク単位。履歴は文字ごとに保持 | Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z |
| クリア | Canvas上のストロークを全削除（元に戻すで復帰可能） | — |
| 保存 | ストロークをグリフとして登録し、メモリ上のフォントを再生成。次の未作成文字へ自動で進む。ストローク0本のときは無効 | Enter |
| スキップ | 保存せず次の未作成文字へ | → |
| 前へ | 一覧上のひとつ前の文字へ | ← |
| 文字チップの削除 | 右クリックまたは長押しでメニュー。作成済みは確認ダイアログを出す | — |

- 作成済みの文字を開いた場合は、保存済みのストロークをCanvasに復元して追記・修正できる。「保存」で上書きする
- 未保存のストロークがある状態で別の文字へ移るときは、「破棄して移動」「保存して移動」を確認する
- 全文字作成完了時は「すべての文字を作成しました」と表示し、プレビュー画面へのボタンを出す

## 5. 手書きストロークからグリフへの変換

画像は経由せず、記録したペンの軌跡（ベクター）から直接フォントの輪郭を作る。変換は同じ入力から常に同じ結果になる純粋関数とし、zipからの復元時にも同じ処理でフォントを再生成する。

### 5.1 変換パイプライン

1. **記録**：各ストロークを `[x, y, pressure]` の配列として保持（x, yは0〜1000、小数点以下1桁に丸める）。前の点から2単位未満の移動は間引く
2. **輪郭化**：perfect-freehandの `getStroke()` で、各ストロークを太さ付きの輪郭ポリゴンに変換。太さなどのパラメータはグリフごとに保存した値を使う
3. **合成**：polygon-clippingの `union()` で全ストロークを合成し、重なりや自己交差のない輪郭の集合にする。「口」の内側のような穴も正しく得られる
4. **簡略化**：Douglas–Peucker法（許容誤差0.8単位前後）で点数を削減。小さすぎる輪郭（面積4平方単位未満）は削除
5. **曲線化**：隣接点の中点を結ぶ二次ベジェ曲線（元の点を制御点とする）で滑らかにする。perfect-freehand公式の `getSvgPathFromStroke` と同じ考え方
6. **座標変換**：Canvas座標（y下向き）→ フォント座標（y上向き、ベースライン=0）。`fontX = x`、`fontY = 880 - y`
7. **向きの正規化**：中間データでは外側の輪郭を時計回り、穴を反時計回りに統一する（TrueTypeの規約）。CFF（.otf）へ書き出すときは向きを反転する
8. **出力**：形式に依存しない中間データ `GlyphOutline` として返す。輪郭は点の配列で、各点は `{ x, y, onCurve }`（座標は整数に丸める）。これはfonteditor-coreのグリフ形式（TrueTypeの二次ベジェ）と同じ構造で、.ttfにはそのまま、.otfにはopentype.jsの `quadraticCurveTo` で変換して渡す（第6章）

### 5.2 ペンのパラメータ（初期値）

| 項目 | 初期値 | 備考 |
| --- | --- | --- |
| size（太さ） | 40単位 | スライダーで15〜100。em1000に対する値 |
| thinning | 0.5 | 筆圧による太さの変化量 |
| smoothing | 0.5 |  |
| streamline | 0.5 | 手ブレの補正 |
| simulatePressure | 筆圧が取れないときtrue |  |

ペン設定はプロジェクト全体の初期値として保存し、各グリフには保存時点の値を記録する。後から初期値を変えても、既存グリフの見た目は変わらない。

### 5.3 エッジケース

- 点が1つだけのストローク（タップしただけ）は、円形の点として輪郭化する（濁点・句読点用）
- polygon-clippingが例外を投げた場合は、合成せず各ストロークの輪郭をそのまま使う（nonzero塗りで表示上は問題ない）。コンソールに警告を出す
- 描画が枠の外にはみ出した場合は、そのまま保持する（切り取らない）
- 1グリフあたりの制御点が3,000を超える場合は、簡略化の許容誤差を段階的に上げて再処理する

## 6. フォント生成仕様

同じ中間データ（第5章の `GlyphOutline`）から、TrueType形式（.ttf）とCFF形式（.otf）の2種類を書き出す。.ttfをメインの出力とし、.otfは補助とする。どちらもWindowsとmacOSにインストールでき、Wordで使えることを必須とする。

| 形式 | ライブラリ | 位置づけ | 備考 |
| --- | --- | --- | --- |
| .ttf | fonteditor-core | メイン（既定） | 二次ベジェの輪郭をそのままglyfに格納するので変換誤差はない。Wordの「ファイルにフォントを埋め込む」とPDF保存に対応させるための本命 |
| .otf | opentype.js | 補助 | 二次ベジェをCFFの三次曲線に変換する（誤差なし）。WordはCFFフォントを.docxに埋め込まず、PDF保存で文字が画像化される報告もあるため、Word用途では.ttfを案内する |

- 6.1〜6.4のメトリクス、送り幅、グリフ、名前は両形式で同じ値を使う。共通の `FontSpec` 型を作り、形式ごとの差はアダプタ（`lib/font/ttf.ts`、`lib/font/otf.ts`）に閉じ込める
- 両形式で同じ見た目になること（同一グリフの輪郭座標・送り幅・メトリクスが一致すること）をテストで確認する

### 6.1 メトリクス

| 項目 | 値 |
| --- | --- |
| unitsPerEm | 1000 |
| ascender / descender | 880 / -120 |
| OS/2 sTypoAscender / sTypoDescender / sTypoLineGap | 880 / -120 / 0 |
| OS/2 usWinAscent / usWinDescent | 1000 / 200（はみ出した描画が欠けないよう余裕を持たせる） |
| hhea lineGap | 0 |

### 6.2 送り幅（advanceWidth）

- **全角文字**（かな、漢字、全角記号など）：1000固定（等幅）。履歴書のような書類で崩れにくいため
- **半角文字**（U+0021〜U+007E、半角カナ）：描画の左右端に合わせたプロポーショナル。描画を左へ寄せ、左右に60単位の余白を付けて送り幅とする（最小250）
- 全角・半角の判定はUnicodeのEast Asian Widthで行い、「W」「F」「A」を全角とする
- 全角・半角の扱いはグリフごとに上書きできる（将来拡張。データには `widthMode` として持たせる）

### 6.3 自動で含めるグリフ

| グリフ | 内容 |
| --- | --- |
| `.notdef`（ID 0） | 枠の中に×を入れた図形。未作成の文字だとわかる形にする |
| U+0020 半角スペース | 空グリフ、送り幅300 |
| U+3000 全角スペース | 空グリフ、送り幅1000 |

### 6.4 名前とメタデータ（name / OS/2 テーブル）

| 項目 | 値 |
| --- | --- |
| familyName | ユーザーが設定（英数字のみ、初期値 `MyHandwriting`） |
| 日本語名（任意） | 設定されていればnameテーブルにjaロケールで追加（例：大澤手書き） |
| styleName | Regular |
| postScriptName | `{familyName}-Regular`（英数字とハイフンのみ、63文字以内） |
| version | `Version 1.{書き出し回数}` を書き出しのたびに加算 |
| uniqueID | `{familyName}-{書き出し日時ISO}` |
| designer | 任意入力 |
| OS/2 fsType | 0（インストール可能。Wordのフォント埋め込みやPDF出力で必要） |
| OS/2 usWeightClass | 400 |
| OS/2 ulCodePageRange | Latin 1とJISのビットを立てる（Windowsで日本語フォントとして認識させるため） |

各ライブラリの既定値で上記が設定されない項目は直接設定する。fonteditor-coreでは `font.get()` で得たテーブル（`head`、`hhea`、`OS/2`、`name`）を書き換えてから `write({ type: 'ttf' })` する。opentype.jsでは `font.tables.os2` や `font.names` を設定する。どちらかの形式で設定できない項目があれば、実装時に報告すること。

### 6.5 生成タイミングとプレビュー用登録

- グリフの保存・削除のたびにフォントを再生成する（300msデバウンス）。変換済みの中間データはグリフ単位でキャッシュし、変更されたグリフだけ再計算する
- プレビュー用に常時生成するのは.ttfのみとする。.otfはダウンロード時とzip保存時に生成する
- 生成した.ttfのArrayBufferを `new FontFace(内部名, buffer)` で `document.fonts` に登録し、プレビューやサムネイルで使う。内部名は再生成ごとに変え（例：`hw-preview-{n}`）、古いFontFaceは削除する（キャッシュ対策）
- アウトラインのあるグリフが0個のときはフォントを生成しない（ダウンロードボタンは無効化）
- ダウンロード時のファイル名は `{familyName}.ttf` / `{familyName}.otf`

## 7. 途中保存・読み込み（zip仕様）

zipにはフォントファイル、グリフごとのベクターJSONとプレビューPNG、全体を束ねる `project.json` を入れる。復元時の正はベクターJSONとし、フォントはそこから再生成する。

### 7.1 ファイル構成

```
{familyName}_{YYYYMMDD-HHmm}.zip
├─ project.json              # マニフェスト（必須）
├─ fontfile/
│   ├─ {familyName}.ttf      # 保存時点のフォント（グリフ0個のときは省略）
│   └─ {familyName}.otf      # 同上
└─ rawdata/
    ├─ vector/
    │   ├─ U+3042.json       # 「あ」のストローク
    │   └─ U+5927.json       # 「大」
    └─ preview/
        ├─ U+3042.png        # 256×256px、白背景に黒
        └─ U+5927.png
```

- ファイル名は文字そのものではなくコードポイント（`U+` ＋4〜6桁の大文字の16進数）にする。`/` や `?` などOSで使えない文字を避けるため
- 未作成の文字も一覧として `project.json` に残し、復元後に続きから描けるようにする

### 7.2 project.json

```json
{
  "format": "handwriting-font-project",
  "formatVersion": 1,
  "appVersion": "0.1.0",
  "savedAt": "2026-11-07T20:30:00+09:00",
  "font": {
    "familyName": "MyHandwriting",
    "familyNameJa": "大澤手書き",
    "designer": "",
    "exportCount": 3
  },
  "defaults": {
    "pen": { "size": 40, "thinning": 0.5, "smoothing": 0.5, "streamline": 0.5 }
  },
  "queue": ["大", "澤", "太", "郎"],
  "previewText": "大澤太郎",
  "glyphs": [
    { "char": "大", "codepoint": "U+5927", "file": "rawdata/vector/U+5927.json" }
  ]
}
```

### 7.3 ベクターJSON（rawdata/vector/U+XXXX.json）

```json
{
  "char": "大",
  "codepoint": "U+5927",
  "canvasSize": 1000,
  "widthMode": "auto",
  "pen": { "size": 40, "thinning": 0.5, "smoothing": 0.5, "streamline": 0.5, "simulatePressure": false },
  "strokes": [
    { "points": [[120.5, 400.0, 0.52], [130.0, 401.2, 0.55]] }
  ],
  "updatedAt": "2026-11-07T20:28:11+09:00"
}
```

- `points` は `[x, y, pressure]`。x, yは0〜1000のCanvas座標（y下向き）、pressureは0〜1
- `widthMode` は `auto`（East Asian Widthで判定）｜ `full` ｜ `half`
- スキーマは型定義と同じ内容でzodなどによるバリデーションを用意する

### 7.4 保存の流れ

1. ヘッダーの「zipで保存」を押す
2. 未保存のストロークがCanvasにあれば「この文字も保存しますか？」と確認する
3. フォントを生成し、各グリフのPNGをOffscreenCanvas（非対応環境では通常のCanvas）で描画する
4. JSZipで組み立て（DEFLATE圧縮）、`<a download>` でダウンロードさせる
5. 「未保存」バッジを消す

### 7.5 読み込みの流れ

1. 「zipを開く」でファイル選択、または画面へのドラッグ＆ドロップ
2. 現在の作業に未保存の変更があれば、上書きしてよいか確認する
3. `project.json` を読み、`format` と `formatVersion` を検証する。新しすぎるバージョンはエラー、古いバージョンはマイグレーション関数を通す
4. 各ベクターJSONを検証して読み込む。壊れたファイルがあってもその文字だけスキップし、読み込めなかった文字を一覧で通知する
5. ベクターからフォントを再生成する（zip内の.ttf / .otfとPNGは読み込みには使わない）
6. 入力ページに移動し、最初の未作成文字を開く

不正なzip対策として、展開後の合計サイズは200MB、ファイル数は20,000を上限とする。想定外のパス（`../` を含むものなど）は無視する。

## 8. フォント適用画面（/preview）

textareaに入力した文章を、生成中のフォントでその下に表示する。履歴書に入れたい文字が揃っているかを確かめるのが主な目的。

### 8.1 画面構成

1. **textarea**：初期値は入力ページの作成済み文字を連結したもの。入力内容はストアに保持し、画面遷移しても消えない（zipにも `previewText` として保存）
2. **表示設定**：文字サイズ（12〜96px、初期24px）、行間（1.0〜2.5、初期1.6）、文字色（黒 / 紺 / 青黒）、縦書きプレビュー（`writing-mode: vertical-rl`、参考表示）
3. **表示エリア**：textareaの値を生成フォントで表示。改行と空白は `white-space: pre-wrap` で保持。罫線の入った便箋風の背景をON/OFFできる
4. **未作成文字の一覧**：テキスト中で未作成の文字を重複なしで列挙し、「入力ページに追加して描く」ボタンで一覧へ追加して入力ページに移動する
5. **ダウンロード**：「.ttfをダウンロード（Word向け・推奨）」「.otfをダウンロード」の2つのボタン

### 8.2 未作成文字の表示

- 「未作成文字の表示」を切り替えられるようにする（初期値は「代替フォント＋ハイライト」）
  - **代替フォント＋ハイライト**：未作成文字を `<span>` で囲んで薄い赤の背景を付け、代替フォント（sans-serif）で表示
  - **代替フォントのみ**：ハイライトなしで自然に表示（実際のWordでの見え方に近い）
  - **.notdef表示**：代替フォントを使わず、生成フォントの `.notdef`（×印の箱）で表示
- 未作成判定はコードポイント単位で行い、改行、半角スペース、全角スペースは対象外とする

### 8.3 グリフが0個のとき

「まだ文字がありません。入力ページで文字を作成してください」と表示し、入力ページへのボタンを出す。

## 9. 使い方ページ（/）

初めての人が、このページだけで「文字を描く→保存→Wordで使う」までたどり着ける内容にする。文章は静的に書き込んでよい。

**掲載内容**

1. **このアプリでできること**：手書き文字からPCにインストールできるフォント（.ttf / .otf）を作れること。データはブラウザの外に送信されないこと
2. **作り方の手順**：文字列を入力 → 1文字ずつ描いて保存 → プレビューで確認 → フォントをダウンロード（Wordで使うなら.ttf）
3. **きれいに描くコツ**：ガイドの内側いっぱいに描く、お手本を使う、ペンタブレットやiPad＋Apple Pencilがおすすめ、住所・氏名・学校名など履歴書で使う文字から作る
4. **途中保存**：「zipで保存」で作業を保存し、「zipを開く」で続きから再開できること。ブラウザの自動保存は保険であり、キャッシュ削除で消えること
5. **フォントのインストール方法**
   - Windows：.ttfを右クリック →「インストール」。作り直した場合は既存のフォントを削除し、Wordを再起動してから入れ直す
   - macOS：.ttfをダブルクリック → Font Bookで「インストール」
6. **Wordで使うときの注意**
   - フォント一覧から設定したフォント名を選ぶ
   - 作っていない文字は別のフォントで表示されるか、箱印になる
   - 提出前にPDFで保存すると、相手のPCにフォントがなくても手書きの見た目のまま届く。Wordのまま渡す場合は「ファイルにフォントを埋め込む」をONにする。どちらも.ttfを使うこと（.otfはWord文書に埋め込めず、PDF保存で文字が画像になる場合がある）
7. **よくある質問**：文字が箱になる、フォントを更新してもWordに反映されない（再起動が必要）、zipを開けない、など

**ページ内のボタン**

- 「新しくはじめる」：フォント名を入力するダイアログ → 入力ページへ
- 「zipを開いて続きから」：ファイル選択 → 読み込み後に入力ページへ
- 作業中のプロジェクトがある場合は「作業を続ける」も表示する

## 10. 非機能要件・対象外

### 10.1 非機能要件

| 項目 | 要件 |
| --- | --- |
| 対応ブラウザ | Chrome / Edge / Safari / Firefox の最新版。iPadOS Safari（Apple Pencil）で描画できること |
| プライバシー | 手書きデータを外部に送信しない。アクセス解析タグも入れない |
| オフライン | 初回読み込み後はオフラインでも動くことが望ましい（PWA化は任意）。外部CDNに依存しない |
| 性能 | グリフ保存からプレビュー反映まで300文字時で0.5秒以内、2,000文字時で2秒以内。描画中にカクつかない（60fps目標） |
| 重い処理 | フォント生成とzip作成は必要に応じてWeb Workerで実行し、UIを止めない |
| 上限 | 1プロジェクトあたりグリフ5,000個までを想定 |
| アクセシビリティ | ボタンにラベルを付ける、キーボードで主要操作ができる |
| 言語 | UIは日本語のみ |
| 品質 | TypeScript strict、ESLint＋Prettier。`lib/` の主要関数にVitestの単体テスト |

### 10.2 対象外（今回は実装しない）

- アカウント、クラウド保存、フォントの共有
- WOFF/WOFF2の書き出し（fonteditor-coreで対応できるため将来の拡張候補）
- カーニング、合字、縦書き用字形（`vert`）、異体字
- ウェイト違い（太字など）のバリエーション
- 紙に書いた文字の画像取り込み（トレース）
- 制御点を直接動かすベジェ編集
- 絵文字、結合文字

これらを後から追加できるよう、データ形式（`formatVersion`、グリフごとの `widthMode` や `pen`）に余地を残してある。

### 10.3 代替案：サーバーサイド生成

ブラウザ版で受け入れ基準（特にWordへの埋め込みとPDF保存）を満たせない場合に限り、フォント生成をサーバーに移す。初期実装では作らない。

- **構成**：Python＋fontTools（`fontBuilder`）でTTF/OTFを生成。必要に応じてOTSで検証し、ttfautohintでヒンティングを付ける
- **送るデータ**：ベクターJSONとフォント設定のみ。生成後にサーバー側でデータを保持しない
- **影響**：「ブラウザ内で完結」の前提が崩れるため、使い方ページとプライバシーの記述を見直す。ホスティング（Cloud Run等）が必要になる
- **備え**：クライアント側は `lib/font` のインターフェース（`GlyphOutline[]` と `FontSpec` を受け取り、ArrayBufferを返す）を保ち、生成の実装だけを差し替えられるようにしておく

## 11. 実装ステップと受け入れ基準

フォント生成という最大の技術リスクを最初に潰し、その後に画面を肉付けする順で進める。各ステップの終わりで動作する状態を保つこと。

### 11.1 実装ステップ

1. **基盤**：Viteプロジェクト作成、ルーティング、共通ヘッダー、型定義（`types/project.ts`）、zustandストア
2. **変換と生成の検証**：`lib/glyph` と `lib/font` を実装し、固定のテスト用ストロークから.ttfと.otfを生成。WindowsとmacOSでインストールし、Wordで表示できること、.ttfが.docxに埋め込めること、WordのPDF保存で文字がテキストのまま（選択・検索できる状態で）残ることをここで確認する。満たせない場合は10.3の代替案を相談する
3. **手書きCanvas**：描画、ガイド、お手本、元に戻す/やり直し、筆圧、ペン設定
4. **入力ページ**：文字列取り込み、文字一覧、保存と次への遷移、プリセット追加、ショートカット
5. **適用画面**：FontFace登録、textareaと表示エリア、未作成文字の表示切替えと一覧
6. **zip保存・読込**：書き出し、読み込み、バリデーション、エラー通知、IndexedDB自動保存と復元
7. **使い方ページと仕上げ**：説明文、レスポンシブ、未保存警告、性能確認（300文字・2,000文字のダミーデータ）

### 11.2 受け入れ基準

- [ ] 「大澤太郎」と入力すると4文字が一覧に並び、描いて保存するたびに次の文字へ進む
- [ ] 保存した文字が、待たずに適用画面で手書きの形で表示される
- [ ] 「口」「回」など穴のある文字や、線が交差・重なる文字が、塗り抜けや欠けなく表示される
- [ ] 濁点や句読点のようなタップだけの点がフォントに反映される
- [ ] ダウンロードした.ttfと.otfをそれぞれWindows 11とmacOSにインストールでき、Wordのフォント一覧に設定した名前で表示される
- [ ] .ttfを使ったWord文書をPDFに保存すると、フォントがテキストとして埋め込まれ（文字を選択・検索できる）、フォント未インストールのPCでも手書きのまま表示される。「ファイルにフォントを埋め込む」をONにした.docxも、別のPCで手書きのまま表示される
- [ ] 全角文字は等幅で、英数字は文字幅に合わせて詰まって並ぶ。行の高さが不自然に広がらない
- [ ] zipで保存 → リロード → zipを開くで、未作成文字を含む一覧・全ストローク・設定・プレビュー文章が完全に復元され、再生成したフォントが保存前と同じ見た目になる
- [ ] zipの中に `project.json`、`fontfile/{名前}.ttf / .otf`、`rawdata/vector/*.json`、`rawdata/preview/*.png` が入っている
- [ ] 壊れたzipや無関係なzipを開いてもアプリが落ちず、わかりやすいエラーが出る
- [ ] リロードしても自動保存から作業を復元できる
- [ ] iPad＋Apple Pencilで、画面がスクロールせず筆圧付きで描ける
- [ ] `lib/` の単体テストが通る（文字列分割、座標変換、輪郭の向き、送り幅計算、zipの往復）
