# 手書きフォント作成サイト 仕様書

最終更新: 2026-11-08

## 1. 概要・目的

自分の手書き文字から、PCにインストールしてWordなどで使えるフォントファイル（.ttf / .otf）を生成するWebサイトを作る。主な用途は履歴書などの書類を手書き風の文字で作成すること。

**前提**

- すべての処理をブラウザ内で完結させる。サーバー、アカウント、外部送信は一切なし（静的サイト）
- ユーザーは文字列を入力し、1文字ずつCanvasに手書きして登録していく
- 複数のプロジェクト（フォント）を持てる。プロジェクトごとにUUIDを振ってブラウザ（IndexedDB）に保存し、URLのクエリ `?uuid=xxx` で開くプロジェクトを決める
- 作業内容はzipで保存・再読み込みできる（バックアップや別のPCへの移動用）。zipにはフォントファイルと手書きの生データ（ベクター＋プレビュー画像）を含める
- 生成したフォントをその場で適用して確認できる画面を用意する

**用語**

| 用語 | 意味 |
| --- | --- |
| グリフ | 1文字分の字形データ |
| ストローク | ペンを置いてから離すまでの1本の線（座標と筆圧の列） |
| em | フォントの基準座標空間。本アプリでは1000×1000単位 |
| プロジェクト | 1つのフォントを作るための作業データ一式（フォント名、設定、全グリフ）。UUIDで識別する |

## 2. 技術スタックとディレクトリ構成

Next.js（App Router）+ React + TypeScriptで実装し、静的エクスポート（`output: 'export'`）でページごとのHTMLを事前に作る。サーバーは持たない（手書きのデータを外部に送らないため。Server ActionsやAPIルートなど、サーバーが必要な機能は使わない）。ビルド成果物は任意の静的ホスティングに置けること。本リポジトリでは次の2つで配信する（10.4）。

- **GitHub Pages**：`main` へのpushでGitHub Actionsからデプロイ。`basePath` を `/MyFontStudio` にする
- **Docker（Nginx）**：ルートの `Dockerfile` でビルドしてNginxで配信し、Render（`render.yaml`）にデプロイする

使い方ページはサーバーコンポーネント（説明文はHTMLに書き出す）、入力ページと適用画面はCanvas・FontFace・IndexedDBなどブラウザの機能を使うのでクライアントコンポーネントとする。

| フレームワーク | Next.js（App Router、静的エクスポート）/ React 19 / TypeScript（strict） | `trailingSlash: true`（`/editor/` → `editor/index.html`） |

## 3. 画面構成とルーティング

3画面構成とし、共通ヘッダーからいつでも移動・保存・読込ができるようにする。

各ページは静的なHTMLとして書き出す。GitHub Pagesでは先頭に `/MyFontStudio` が付く。開くプロジェクトはクエリの `?uuid=` で決める（静的エクスポートなので、パスにuuidを入れる動的なルートは使わない）。

| パス | 画面 | 内容 |
| --- | --- | --- |
| `/` | 使い方 | アプリの説明、手順、インストール方法。「新しくはじめる」「zipを開いて続きから」ボタン、プロジェクトの一覧 |
| `/editor/?uuid={uuid}` | 入力ページ | 文字列入力、文字一覧、手書きCanvas、グリフ登録 |
| `/preview/?uuid={uuid}` | 適用画面 | textareaの入力を生成フォントで表示、.ttf / .otfダウンロード |

**共通ヘッダー**

- 左：アプリ名、ナビ（使い方 / 入力 / プレビュー）
- 中央：プロジェクトの切り替え（開いているプロジェクトのフォント名を表示。メニューに、このブラウザのプロジェクトの一覧（開いているものに印）・「新しいプロジェクト」・「ZIPを読み込む」（新しいプロジェクトとして追加）。描きかけのストロークがあれば、切り替える前に確かめる。プレビューを見ているときはプレビューのまま切り替える）、「編集」（フォント名・日本語名・作者）、登録済み文字数
- 右：「zipで保存」「フォントをダウンロード」（.ttf / .otfを選べるドロップダウン。既定は.ttf。アウトラインのあるグリフが0個のときは無効）
- zipに保存していない変更（線を描く・元に戻すなどの描いた履歴の変更も含む。描いた履歴もzipに入るため）がある場合は「zip 未保存」バッジを出す（プロジェクトはブラウザに自動で保存しているので、バッジは「zipに書き出していない」という意味。ツールチップでも説明する）
- ブラウザへの保存が終わっていないときは、タブを閉じる際に `beforeunload` で警告する（描きかけの線も描いた履歴としてすぐに保存するので、それだけでは警告しない）
- ブラウザへの保存に失敗したとき（容量の不足・プライベートブラウズなど）は、エラーを通知し（容量の不足なら、zipで保存してから不要なプロジェクトを消すよう案内する）、ヘッダーに「ブラウザに保存できていません」を出す。失敗が続くあいだは通知を重ねず、保存できていない変更があるのでタブを閉じる際に警告する。次の保存に成功したら表示を戻して知らせる

**状態の共有**

開いているプロジェクトはzustandストアで保持し、画面遷移しても失われないようにする。

- **保存**：プロジェクトごとにIndexedDBへ保存する。設定・文字一覧・文章とグリフ・描いた履歴のある文字の一覧は `myfontstudio:project:{uuid}`、グリフは `…:glyph:{U+XXXX}`、描いた履歴は `…:drawing:{U+XXXX}` と文字ごとに分け、変わった文字だけを書く（1本描くたびにプロジェクト全体を書かないように）。一覧（フォント名・文字数・更新日時の要約）は `myfontstudio:projects` に持ち、書く値と一覧は1つのトランザクションで書く。前の形式（全体を1つの値に保存していたもの）は、読み込んだときに今の形式に書き直す。保存してあるのに読めないとき（読み込みのエラー・データの形が正しくない・新しい版の形式・一覧にあるのにデータがない）は、空のプロジェクトとして開かず（そのキーには書き込まない）、「プロジェクトを開けません」と理由（再読み込み・zipから開く）を出す。保存していない（キーがない）ときだけ、そのuuidで新しく始める。描いた履歴は1文字5,000操作を超えたら、古い操作をその時点の線にまとめて4,000操作に減らす。文字の追加・グリフの保存・描いた線・フォントの設定の変更はすぐに、プレビューの文章やペンの設定（太さのスライダーはドラッグ中に何度も変わる）など頻繁に変わるものは500ms待ってまとめて保存する。文字が1つもない新しいプロジェクトは、「新しくはじめる」で作ったもの以外は保存しない
- **開き方**：入力ページと適用画面は `?uuid=xxx` のプロジェクトを開く。uuidがなければ、開いているプロジェクト（なければ新しいプロジェクト）のuuidをURLに付ける。保存していないuuid（文字を追加する前に再読み込みした場合、削除したプロジェクトのブックマークなど）は、そのuuidで新しく始め、「このブラウザに保存されていないので、新しいプロジェクトとして始めます」と知らせる。同じ名前のプロジェクトが複数あるときは、一覧とメニューにuuidの先頭8文字を添えて見分けられるようにする。プロジェクトを切り替えたときは、プレビュー用のフォントを待たずに作り直す。uuidの形（小文字のUUID）が正しくなければ「プロジェクトを開けません」と表示する
- **一覧**：使い方ページに、このブラウザのプロジェクトを新しく更新した順に並べ、開く・削除ができる
- **永続化**：ブラウザは空き容量が足りなくなるとサイトのデータを自動で消すことがあるので、初めてプロジェクトを保存するときに `navigator.storage.persist()` で永続化を頼む（許可するかはブラウザが決める）。使い方ページに、永続化されているか・使用量（`navigator.storage.estimate()`）を表示し、永続化されていなければ「データを消されないようにする」ボタンで頼み直せる。閲覧データの削除では永続化していても消えるので、zipでの保存も案内する
- **複数のタブ**：同じプロジェクトを編集できるタブは1つだけにする（2つのタブで編集すると、あとから保存した方で上書きされるため）。Web Locks APIでプロジェクトごとの排他のロックを取り、取れなかったタブには「このプロジェクトはほかのタブで開いています」と出して編集させない。「このタブで編集する」を押すと、BroadcastChannelでほかのタブに知らせ、ほかのタブは保存を済ませてから編集を止める。押したタブは保存されている最新の内容を読み直して編集を始める。ロックは、そのプロジェクトを開いている間（使い方ページに移っても）持ち続け、ロックを持っているタブだけがプロジェクトを保存する（ロックを確かめている間の変更は、ロックが取れてから保存する。500ms待っている保存も、書く時点で確かめる）。ロックを持っていないタブでは、ヘッダーの「編集」「zipで保存」「フォントをダウンロード」と保存のショートカットも使えない（そのタブの古い内容で上書き・書き出しをしないように）。IndexedDBへの書き込みも、タブをまたぐロックで順番に行う。Web Locks APIがないブラウザでは確かめない
- **引き継ぎ**：前の版の自動保存（プロジェクトが1つだけ。キー `myfontstudio:autosave`）があれば、1つのプロジェクトとして引き継ぐ

**レイアウト**

PC（幅1280px以上）とタブレット（iPad等、幅768px以上）を主対象とする。スマートフォンでは崩れない程度に縦積みで表示すればよい。

## 4. 入力ページ（/editor）

文字列を入力すると未作成の文字が順にCanvasに展開され、描いて「保存」を押すとその文字のグリフが登録され、次の文字へ進む。

### 4.1 画面構成（上から順に）

1. **文字列入力欄**：複数行のtextarea＋「追加」ボタン（Ctrl/Cmd+Enterでも追加。Enterは改行）。住所・氏名などを複数行でまとめて入力・貼り付けできる（改行は取り込み時に除外される）
2. **プリセット追加**：「ひらがな」「カタカナ」「数字」「英字」「記号」のボタン。押すと「ひらがなを85文字追加しますか？」のように、まだ一覧にない文字の数と先頭の文字を示して確かめてから、その文字群を一覧に追加する（取り込みのルールは4.2と同じ。すべて一覧にあれば確かめずにその旨を知らせる）
   - ひらがな：U+3041〜U+3093（小書きを含む）とゝゞ
   - カタカナ：U+30A1〜U+30F6（小書きを含む）とーヽヾ
   - 数字：0〜9（半角）
   - 英字：A〜Z、a〜z（半角）
   - 記号：半角のASCII記号（`!"#$%&'()*+,-./:;<=>?@[\]^_`{|}~`）と、全角の句読点・括弧など（。、・「」『』（）【】！？〜…）
3. **文字一覧（CharQueue）**：追加した文字をチップで横並び表示。作成済みはサムネイル付きで緑、未作成はグレー、編集中は枠線で強調。クリックでその文字の編集に移る。並び替えと絞り込みができる（設定は画面を移動しても保つが、プロジェクトには保存しない）
   - 並び順：登録順（一覧に追加した順）・文字コード順・更新日時順（グリフを保存した日時。未作成の文字は向きによらず最後）。それぞれ昇順・降順
   - 検索：入力した文字そのもの（「大澤太郎」と入れるとその4文字）か、コードポイントの一部（「U+30」「3042」。大文字・小文字は区別しない）
   - 作成状況：すべて・未作成・作成済み
   - 文字の種類：ひらがな・カタカナ（長音符を含む）・漢字（々を含む）・英字・数字・記号・その他
   - 絞り込み中は表示している文字数と「絞り込みを解除」を出す。「前へ」「スキップ」「次の未作成文字」は、並び替え・絞り込みによらず一覧（登録順）で決める
4. **編集中の文字**：大きく表示し、コードポイント（U+3042）も添える
5. **手書きCanvas**（正方形、表示サイズは画面に合わせて360〜560px）
6. **操作ボタン**：元に戻す / やり直し / クリア / 前へ / スキップ / **保存**
7. **ペン設定**：太さ（スライダー）、筆圧の有無（ON：筆圧が取れれば使い、取れなければ速度から推定する／OFF：太さ一定）、お手本表示のON/OFF

### 4.2 文字列の取り込みルール

- 入力文字列は `Array.from()` でコードポイント単位に分割する（サロゲートペア対応）
- 重複は除外し、入力順を維持して一覧の末尾に追加する
- 空白・改行・制御文字（`\p{White_Space}`、`\p{Cc}`、`\p{Cf}`）は黙って除外する（半角スペースと全角スペースはフォント生成時に自動で含める）
- NFC正規化をかけてから取り込む（「か」＋結合用濁点は「が」1文字になる）
- 絵文字や結合文字は対象外とし、取り込み時に「対応していない文字」として通知する。対象外とするのは、結合文字（`\p{M}`。NFC後も単独で残る結合用濁点など）、異体字セレクタ（U+FE00〜U+FE0F、U+E0100〜U+E01EF）、絵文字表示が既定の文字（`\p{Emoji_Presentation}`）、国旗用の地域指示子（`\p{Regional_Indicator}`）、私用領域（`\p{Co}`）、サロゲート単体（`\p{Cs}`）。©や☆のようにテキスト表示が既定の記号は取り込める

### 4.3 Canvasの仕様

- 内部座標は0〜1000の正方形（em座標）に正規化して記録する。表示サイズが変わってもデータは不変
- `devicePixelRatio` を考慮して高解像度で描画する
- **ガイド線**：外枠、十字の中心線（破線）、ベースライン（y=880）、推奨描画範囲（内側余白50を示す枠）。半角文字のときは英字用のガイド（x-height：フォント座標500＝Canvasのy=380、キャップハイト：フォント座標700＝Canvasのy=180）も表示する。Canvasのy=0がフォント座標の880（ascender）、y=1000が-120（descender）にあたる
- **お手本**：編集中の文字を既存フォント（sans-serif）で薄いグレーで背景に表示する。ON/OFF切り替え可。お手本はグリフデータには含めない
- **入力**：Pointer Eventsで扱い、マウス・タッチ・ペン（Apple Pencil等）に対応。`touch-action: none` でスクロールを抑止。ペン使用時はパームリジェクションとしてtouch入力を無視する（ペンを初めて検出したときに自動でONにして知らせる。利用者が「指の入力を無視」を自分で切り替えたら、その値をブラウザに覚えておき、ペンを検出しても変えない）
- 筆圧は `PointerEvent.pressure` を使う。マウスなど筆圧が取れない場合（`pointerType` が `pen` 以外）は速度から筆圧を推定する（perfect-freehandの `simulatePressure`）。推定するかどうかはストロークごとに記録する（7.3）
- 描画中の表示は、保存後のフォントと同じ輪郭化（第5章の手順2、perfect-freehand）で各ストロークを描き、nonzeroで塗る。合成（手順3）以降は描画のたびには行わないが、塗った結果は合成後と同じ形になるので、見たままの形がフォントになる

### 4.4 操作の挙動

| 操作 | 挙動 | ショートカット |
| --- | --- | --- |
| 元に戻す / やり直し | ストローク単位。履歴は文字ごとに保持し、プロジェクトに保存する（ブラウザとzip）。再読み込み・プロジェクトの切り替え・zipからの読み込みのあとも、グリフとして保存したあとも、その文字の履歴で元に戻せる | Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z |
| クリア | Canvas上のストロークを全削除（元に戻すで復帰可能） | — |
| 保存 | ストロークをグリフとして登録し、メモリ上のフォントを再生成。次の未作成文字へ自動で進む。ストローク0本のときは無効。線もペンも保存済みのグリフと同じなら保存し直さずに進むだけ（「zip 未保存」・更新日時を変えない）。ペンだけを変えたときは、文字全体の見た目が変わるので保存し直す | Enter、Ctrl/Cmd+S |
| zipで保存 | ヘッダーの「zipで保存」と同じ（7.4）。入力ページ以外ではCtrl/Cmd+Sも「zipで保存」 | Ctrl/Cmd+Shift+S |
| スキップ | 保存せず次の未作成文字へ | → |
| 前へ | 一覧上のひとつ前の文字へ | ← |
| 文字チップの削除 | 右クリックまたは長押し、または文字のボタンにフォーカスがあるときのDelete・Backspaceで確認ダイアログを出し、「削除」で一覧から消す（未作成の文字でも確かめる。作成済みの文字は、字形も消えて元に戻せないことを書き添える）。削除の方法は、スクリーンリーダーにも伝える（`aria-describedby`） | Delete、Backspace |

- Ctrl/Cmd+S・Ctrl/Cmd+Shift+Sは、テキスト入力にフォーカスがあっても働く（テキストの編集と重ならないため）。ブラウザ標準の「ページを保存」は止める。ダイアログが開いているときと変換中（IME）は働かない
- ショートカット（Enter、←、→）は、文字列入力欄などのテキスト入力にフォーカスがないときだけ働く。文字列入力欄（textarea）でのEnterは改行、Ctrl/Cmd+Enterは「追加」になる。Ctrl/Cmd+Zも、テキスト入力にフォーカスがあるときはブラウザの既定の動作（文字の取り消し）を優先する
- 作成済みの文字を開いた場合は、保存済みのストロークをCanvasに復元して追記・修正できる。「保存」で上書きする
- 未保存のストロークがある状態で別の文字へ移るときは、「破棄して移動」「そのまま移動」「保存して移動」を確認する（「そのまま移動」は描きかけのまま残し、あとで戻って続きを描ける。「破棄して移動」はその文字の履歴を消して保存済みの線に戻す）
- 描いた履歴は「操作の記録（線を足す・クリア）」と「どこまで適用しているか」で持つ（7.3.1）。元に戻したあとに新しく描くと、やり直しできる操作は捨てる
- 全文字作成完了時は「すべての文字を作成しました」と表示し、プレビュー画面へのボタンを出す

## 5. 手書きストロークからグリフへの変換

画像は経由せず、記録したペンの軌跡（ベクター）から直接フォントの輪郭を作る。変換は同じ入力から常に同じ結果になる純粋関数とし、zipからの復元時にも同じ処理でフォントを再生成する。

### 5.1 変換パイプライン

1. **記録**：各ストロークを `[x, y, pressure]` の配列として保持（x, yは0〜1000、小数点以下1桁に丸める）。前の点から2単位未満の移動は間引く
2. **輪郭化**：perfect-freehandの `getStroke()` で、各ストロークを太さ付きの輪郭ポリゴンに変換。太さなどのパラメータはグリフごとに保存した値を使う
3. **合成**：polygon-clippingの `union()` で全ストロークを合成し、重なりや自己交差のない輪郭の集合にする。「口」の内側のような穴も正しく得られる
4. **簡略化**：Douglas–Peucker法（許容誤差0.8単位前後）で点数を削減。小さすぎる輪郭（面積4平方単位未満）は削除
5. **曲線化**：隣接点の中点を結ぶ二次ベジェ曲線（元の点を制御点とする）で滑らかにする。perfect-freehand公式の `getSvgPathFromStroke` と同じ考え方。中点はonCurveの点として明示的に入れる（TrueTypeの「暗黙のonCurve点」には頼らない。整数に丸めたあとも.ttfと.otfで同じ点になるようにするため）
6. **座標変換**：Canvas座標（y下向き）→ フォント座標（y上向き、ベースライン=0）。`fontX = x`、`fontY = 880 - y`
7. **向きの正規化**：中間データでは外側の輪郭を時計回り、穴を反時計回りに統一する（TrueTypeの規約。y上向きの座標で見た向き）。CFF（.otf）へ書き出すときは向きを反転する
8. **出力**：形式に依存しない中間データ `GlyphOutline` として返す。輪郭は点の配列で、各点は `{ x, y, onCurve }`（座標は整数に丸める）。onCurveの点とoffCurveの点が交互に並ぶ（直線の区間はonCurveが続く）。これはfonteditor-coreのグリフ形式（TrueTypeの二次ベジェ）と同じ構造で、.ttfにはそのまま、.otfにはopentype.jsの `quadraticCurveTo` で変換して渡す（第6章）

### 5.2 ペンのパラメータ（初期値）

| 項目 | 初期値 | 備考 |
| --- | --- | --- |
| size（太さ） | 40単位 | スライダーで15〜100。em1000に対する値 |
| thinning | 0.5 | 筆圧による太さの変化量 |
| smoothing | 0.5 |  |
| streamline | 0.5 | 手ブレの補正 |
| simulatePressure | 筆圧が取れないときtrue | ストロークごとに記録する（7.3）。筆圧OFFのときはfalseで、pressureを0.5に固定する（太さ一定） |

ペン設定はプロジェクト全体の初期値として保存し、各グリフには保存時点の値を記録する。後から初期値を変えても、既存グリフの見た目は変わらない。

### 5.3 エッジケース

- 点が1つだけのストローク（タップしただけ）は、円形の点として輪郭化する（濁点・句読点用）
- polygon-clippingが例外を投げた場合は、合成せず各ストロークの輪郭をそのまま使う（nonzero塗りで表示上は問題ない）。コンソールに警告を出す
- 描画が枠の外にはみ出した場合は、そのまま保持する（切り取らない）。ただし、描くときに記録する点は、左右は枠の外200まで、上下はWindowsで欠けない範囲（usWinAscent・usWinDescentの内側。Canvasのy=-120〜1080）から線の太さの半分（筆圧で最も太くなったとき）を引いた範囲に収める（Canvasの外までペンを動かしても、その範囲の端に沿った線になる）。行の高さが変わるので、usWinAscent・usWinDescentは描画に合わせて広げない（6.1）
- Canvasでは枠の外は見えないので、枠の外にはみ出した線があれば、Canvasの下に「枠の外にはみ出した線があります」と出す。文字一覧のサムネイルとzipのプレビューPNGも、Canvasと同じく枠の中だけを表示する
- 1グリフあたりの制御点が3,000を超える場合は、簡略化の許容誤差を段階的に上げて再処理する

## 6. フォント生成仕様

同じ中間データ（第5章の `GlyphOutline`）から、TrueType形式（.ttf）とCFF形式（.otf）の2種類を書き出す。.ttfをメインの出力とし、.otfは補助とする。どちらもWindowsとmacOSにインストールでき、Wordで使えることを必須とする。

| 形式 | ライブラリ | 位置づけ | 備考 |
| --- | --- | --- | --- |
| .ttf | fonteditor-core | メイン（既定） | 二次ベジェの輪郭をそのままglyfに格納するので変換誤差はない。Wordの「ファイルにフォントを埋め込む」とPDF保存に対応させるための本命 |
| .otf | opentype.js | 補助 | 二次ベジェをCFFの三次曲線に変換する（数学的には誤差なしで変換できるが、opentype.jsが三次の制御点を整数に丸めるため、0.5単位以内の差が出る。見た目には影響しない）。WordはCFFフォントを.docxに埋め込まず、PDF保存で文字が画像化される報告もあるため、Word用途では.ttfを案内する |

- 6.1〜6.4のメトリクス、送り幅、グリフ、名前は両形式で同じ値を使う。共通の `FontSpec` 型を作り、形式ごとの差はアダプタ（`lib/font/ttf.ts`、`lib/font/otf.ts`）に閉じ込める
- 両形式で同じ見た目になること（同一グリフのonCurveの点・送り幅・メトリクス・名前・cmapが一致し、輪郭の範囲の差が1単位以内であること）をテストで確認する。fontToolsとOTSでの確認もCIで行う（`frontend/scripts/check-fonts.py`）

### 6.1 メトリクス

| 項目 | 値 |
| --- | --- |
| unitsPerEm | 1000 |
| デザイン上のascender / descender（Canvasの上端・下端） | 880 / -120 |
| OS/2 sTypoAscender / sTypoDescender / sTypoLineGap | 880 / -120 / 0 |
| OS/2 usWinAscent / usWinDescent | 1000 / 200（はみ出した描画が欠けないよう余裕を持たせる） |
| hhea ascender / descender / lineGap | 1000 / -200 / 0（usWinと同じ値） |
| OS/2 fsSelection | 0x40（REGULAR。USE_TYPO_METRICSは立てない） |
| OS/2 sxHeight / sCapHeight | 500 / 700（Canvasのガイドと同じ） |

行の高さは、WindowsではusWinAscent＋usWinDescent（1200）、macOSではhheaのascender−descender＋lineGapで決まる。hheaを880 / -120にするとmacOSだけ行の高さが1000になり、OSによって行の間隔が変わる（はみ出した描画が上下の行と重なる）。そのため、hheaはusWinと同じ1000 / -200にそろえる。

### 6.2 送り幅（advanceWidth）

- **全角文字**（かな、漢字、全角記号など）：1000固定（等幅）。履歴書のような書類で崩れにくいため
- **半角文字**（U+0021〜U+007E、半角カナなど）：描画の左右端に合わせたプロポーショナル。描画の左端が x=60 になるよう平行移動し、描画の幅＋左右の余白60×2を送り幅とする。送り幅が最小の250に満たないときは250とし、描画をその中央に置く
- 全角・半角の判定はUnicodeのEast Asian Widthで行い、「W」「F」「A」を全角、それ以外（「Na」「H」「N」）を半角とする。ただし「A」のうちラテン文字（éなど）は半角とする（「N」のñなどと幅をそろえるため。×・÷・°・ギリシャ文字などは全角のまま）
- 全角・半角の扱いはグリフごとに上書きできる（将来拡張。データには `widthMode` として持たせる）

### 6.3 自動で含めるグリフ

| グリフ | 内容 |
| --- | --- |
| `.notdef`（ID 0） | 枠の中に×を入れた図形。未作成の文字だとわかる形にする。送り幅1000 |
| U+0020 半角スペース | 空グリフ、送り幅300 |
| U+3000 全角スペース | 空グリフ、送り幅1000 |

### 6.4 名前とメタデータ（name / OS/2 テーブル）

| 項目 | 値 |
| --- | --- |
| familyName | ユーザーが設定（英数字のみ、1〜31文字、初期値 `MyHandwriting`。WindowsのGDIは32文字以上のファミリー名を扱えないため） |
| 日本語名（任意） | 設定されていればnameテーブルに日本語（Windows：言語ID 0x0411）で追加（例：大澤手書き）。31文字以内 |
| styleName | Regular |
| postScriptName | `{familyName}-Regular`（英数字とハイフンのみ、63文字以内） |
| version | `Version {1 + 書き出し回数 / 1000 を小数3桁で}`（例：3回目は `Version 1.003`）。headの `fontRevision` も同じ値。`1.10` のような書き方だと `1.9` より古く見えるため、桁をそろえる |
| uniqueID | `{familyName}-{書き出し日時ISO}` |
| designer | 任意入力 |
| OS/2 fsType | 0（インストール可能。Wordのフォント埋め込みやPDF出力で必要） |
| OS/2 usWeightClass | 400 |
| OS/2 ulUnicodeRange | 含まれる文字から計算する（基本ラテン、ひらがな、カタカナ、CJK統合漢字など） |
| OS/2 ulCodePageRange | Latin 1（bit 0）とJIS（bit 17）のビットを立てる（Windowsで日本語フォントとして認識させるため） |
| OS/2 achVendID | `NONE` |

「書き出し回数」は、フォントのダウンロードとzip保存のたびに1加算する（プレビュー用の生成では加算しない）。加算するのは書き出しに成功したときで、取り消し・失敗では加算しない（書き出すファイルには加算したあとの値を入れる）。

**ライブラリの制約と対応（実装時の調査結果）**

- fonteditor-coreのnameテーブルは英語（Windowsの0x0409とMac）しか書けず、日本語名を設定できない。また、OS/2の `ulUnicodeRange2` を固定値で上書きし、maxpの `maxZones` を0にする
- opentype.jsは `font.tables.os2` でOS/2を上書きできるが、nameテーブルの扱いがfonteditor-coreと異なる

そのため、どちらの形式も、ライブラリで書き出したあとのバイナリに対して、`name` テーブルを自前で組み立てたものに差し替え、`head`・`hhea`・`OS/2`・`maxp` の上記の値を書き換え、チェックサムを計算し直す（`lib/font/sfnt.ts`）。これにより、名前とメトリクスは両形式で必ず同じ値になる。

### 6.5 生成タイミングとプレビュー用登録

- グリフの保存・削除のたびにフォントを再生成する（300msデバウンス）。変換済みの中間データはグリフ単位でキャッシュし、変更されたグリフだけ再計算する
- プレビュー用に常時生成するのは.ttfのみとする。.otfはダウンロード時とzip保存時に生成する
- 生成した.ttfのArrayBufferを `new FontFace(内部名, buffer)` で `document.fonts` に登録し、プレビューやサムネイルで使う。内部名は再生成ごとに変え（例：`hw-preview-{n}`）、古いFontFaceは削除する（キャッシュ対策）
- アウトラインのあるグリフが0個のときはフォントを生成しない（ダウンロードボタンは、作成済みのグリフがないときに無効化する。プレビュー用のフォントの生成とは関係なく、ダウンロードのときに作る）
- 生成に失敗したら、プレビューに理由と「もう一度作る」を出す（前に作ったフォントがあれば、それで表示していることを出す）。プロジェクトを切り替えたら、前のプロジェクトのフォントは使わない。登録を待っている間に新しい生成が先に登録を終えたら、古い生成は登録しない
- ダウンロード時のファイル名は `{familyName}.ttf` / `{familyName}.otf`
- グリフとして保存していない描きかけの線があれば、ダウンロードの前に「この文字も保存しますか？」と確かめる（zipの保存と同じ。保存しない文字はフォントに入らない）

## 7. 途中保存・読み込み（zip仕様）

zipにはフォントファイル、グリフごとのベクターJSONとプレビューPNG、全体を束ねる `project.json` を入れる。復元時の正はベクターJSONとし、フォントはそこから再生成する。

### 7.1 ファイル構成

```
{familyName}_{YYYYMMDD-HHmm}.zip
├─ project.json              # マニフェスト（必須）
├─ fontfile/
│   ├─ {familyName}.ttf      # 保存時点のフォント（グリフ0個のときは省略）
│   └─ {familyName}.otf      # 同上
└─ rawdata/
    ├─ vector/
    │   ├─ U+3042.json       # 「あ」のストローク
    │   └─ U+5927.json       # 「大」
    ├─ preview/
    │   ├─ U+3042.png        # 256×256px、白背景に黒
    │   └─ U+5927.png
    └─ history/
        ├─ U+3042.json       # 「あ」の描いた履歴（元に戻す/やり直し）
        └─ U+6FA4.json       # 描きかけ（グリフとして未保存）の文字の履歴も入る
```

- ファイル名は文字そのものではなくコードポイント（`U+` ＋4〜6桁の大文字の16進数）にする。`/` や `?` などOSで使えない文字を避けるため
- 未作成の文字も一覧として `project.json` に残し、復元後に続きから描けるようにする

### 7.2 project.json

```json
{
  "format": "handwriting-font-project",
  "formatVersion": 2,
  "appVersion": "0.1.0",
  "savedAt": "2026-11-07T20:30:00+09:00",
  "font": {
    "familyName": "MyHandwriting",
    "familyNameJa": "大澤手書き",
    "designer": "",
    "exportCount": 3
  },
  "defaults": {
    "pen": { "size": 40, "thinning": 0.5, "smoothing": 0.5, "streamline": 0.5 },
    "usePressure": true,
    "showModel": true
  },
  "queue": ["大", "澤", "太", "郎"],
  "previewText": "大澤太郎",
  "glyphs": [
    { "char": "大", "codepoint": "U+5927", "file": "rawdata/vector/U+5927.json" }
  ],
  "histories": [
    { "char": "大", "codepoint": "U+5927", "file": "rawdata/history/U+5927.json" }
  ]
}
```

- `formatVersion` は2（1は描いた履歴がない形式。1のzipも読み込め、履歴は保存済みの線から作る）

### 7.3 ベクターJSON（rawdata/vector/U+XXXX.json）

```json
{
  "char": "大",
  "codepoint": "U+5927",
  "canvasSize": 1000,
  "widthMode": "auto",
  "pen": { "size": 40, "thinning": 0.5, "smoothing": 0.5, "streamline": 0.5, "simulatePressure": false },
  "strokes": [
    { "points": [[120.5, 400.0, 0.52], [130.0, 401.2, 0.55]], "simulatePressure": false }
  ],
  "updatedAt": "2026-11-07T20:28:11+09:00"
}
```

- `points` は `[x, y, pressure]`。x, yはCanvas座標（y下向き。0〜1000が枠の中で、はみ出した点はその外の値になる）、pressureは0〜1
- ストロークの `simulatePressure` は、そのストロークで筆圧を速度から推定したか。省略したときはグリフの `pen.simulatePressure` を使う（マウスとペンを1文字の中で混ぜても、見たままの形になるようにするため）
- `defaults.usePressure`・`defaults.showModel` は、ペン設定の「筆圧の有無」「お手本表示」
- `widthMode` は `auto`（East Asian Widthで判定）｜ `full` ｜ `half`
- スキーマは型定義と同じ内容でzodなどによるバリデーションを用意する

### 7.3.1 描いた履歴（rawdata/history/U+XXXX.json）

```json
{
  "char": "大",
  "codepoint": "U+5927",
  "history": {
    "ops": [
      { "type": "add", "stroke": { "points": [[120.5, 400.0, 0.52]], "simulatePressure": false } },
      { "type": "clear" },
      { "type": "add", "stroke": { "points": [[130.0, 401.2, 0.55]] } }
    ],
    "position": 2
  }
}
```

- `ops` は操作の記録（`add`：線を足す、`clear`：すべて消す）。`ops` の先頭から `position` 個を順に適用したものが、今Canvasにある線。`position` より後ろはやり直しできる操作
- 元に戻すたびに線の一覧を丸ごと複製しないよう、操作の記録で持つ（データの大きさは、これまでに描いた線の合計で済む）
- 操作が1つもない文字は入れない。壊れた履歴は、その文字の履歴だけ読み込まずに通知する（字形は読み込む）
- ブラウザ（IndexedDB）にも、プロジェクトの `drawings` として同じ形で保存する

### 7.4 保存の流れ

1. ヘッダーの「zipで保存」を押す（プロジェクトを開いていないとき（使い方ページを直接開いた直後・開いていたものを削除したあと）はボタンを無効にし、ショートカットでも保存せずに「プロジェクトを開いてから保存してください」と知らせる）（保存の途中は、ボタン・ショートカットのどちらからも重ねて始めない）
2. グリフとして保存していない描きかけの線があれば「この文字も保存しますか？」と確認する（保存しない・保存する・キャンセル。描いた履歴は「保存しない」でもzipに入る）
3. 輪郭は画面のスレッドでグリフごとにキャッシュしたもの（プレビュー用のフォントを作るときに計算してある。ないものだけ区切って計算する）を使う。Web Workerで、その輪郭からフォント（.ttf・.otf）を生成し、各グリフのPNGをOffscreenCanvasで描画し、JSZipで組み立てる（DEFLATE圧縮）。画面の左下に進み具合と「取り消す」を出す
4. `<a download>` でダウンロードさせる
5. 書き出し回数を1加算し、「zip 未保存」バッジを消す。zipに入るのは手順1の時点の内容なので、保存の途中に変更があればバッジは残す。ブラウザの保存のダイアログで取り消されてもページからは分からないので、知らせる文言で「取り消したときはもう一度」と案内する

### 7.5 読み込みの流れ

1. ヘッダーのプロジェクトの切り替えメニューの「ZIPを読み込む」・使い方ページの「zipを開いて続きから」でファイル選択、または画面へのドラッグ＆ドロップ
2. 新しいUUIDのプロジェクトとして読み込む（開いているプロジェクトは上書きしない）
3. `project.json` を読み、`format` と `formatVersion` を検証する。新しすぎるバージョンはエラー、古いバージョンはマイグレーション関数を通す
4. 各ベクターJSONを検証して読み込む。壊れたファイルがあってもその文字だけスキップし、読み込めなかった文字を一覧で通知する
5. ベクターからフォントを再生成する（zip内の.ttf / .otfとPNGは読み込みには使わない）
6. 入力ページ（`/editor/?uuid={新しいuuid}`）に移動し、最初の未作成文字を開く

不正なzip対策として、展開後の合計サイズは200MB、ファイル数は20,000を上限とする（展開する前に、zipの中央ディレクトリにある展開後のサイズで確かめる。この値は偽れるので、展開しながら実際の大きさも数え、超えたら展開を止める。1ファイルは32MBまで）。想定外のパス（`../` を含むもの、絶対パス、`project.json`・`rawdata/vector/U+XXXX.json`・`rawdata/history/U+XXXX.json` 以外のもの）は読まない。zip の中のフォント（`fontfile/`）とPNG（`rawdata/preview/`）は読み込みに使わない（手順5）。

## 8. フォント適用画面（/preview）

textareaに入力した文章を、生成中のフォントでその下に表示する。履歴書に入れたい文字が揃っているかを確かめるのが主な目的。

### 8.1 画面構成

1. **textarea**：初期値は入力ページの作成済み文字を連結したもの（プロジェクトを開いてから初めてプレビューを表示したとき、文章が空なら入れる。利用者が消して空にした文章は埋め直さない）。入力内容はストアに保持し、画面遷移しても消えない（zipにも `previewText` として保存）
2. **表示設定**：文字サイズ（12〜96px、初期24px）、行間（1.0〜2.5、初期1.6）、文字色（黒 / 紺 / 青黒）、縦書きプレビュー（`writing-mode: vertical-rl`、参考表示）
3. **表示エリア**：textareaの値を生成フォントで表示。改行と空白は `white-space: pre-wrap` で保持。罫線の入った便箋風の背景をON/OFFできる
4. **未作成文字の一覧**：テキスト中で未作成の文字を重複なしで列挙し、「入力ページに追加して描く」ボタンで一覧へ追加して入力ページに移動する（通知には実際に追加した文字数を出し、すでに一覧にある文字はその数を添える）
5. **ダウンロード**：「.ttfをダウンロード（Word向け・推奨）」「.otfをダウンロード」の2つのボタン

### 8.2 未作成文字の表示

- 「未作成文字の表示」を切り替えられるようにする（初期値は「代替フォント＋ハイライト」）
  - **代替フォント＋ハイライト**：未作成文字を `<span>` で囲んで薄い赤の背景を付け、代替フォント（sans-serif）で表示
  - **代替フォントのみ**：ハイライトなしで自然に表示（実際のWordでの見え方に近い）
  - **.notdef表示**：未作成文字を、生成フォントの `.notdef` と同じ形（×印の箱）で表示する。CSSではフォントにない文字は必ず別のフォントで表示される（フォールバックを止める方法がない）ため、ブラウザに `.notdef` そのものを表示させることはできない。そこで、`.notdef` と同じ形のインラインのSVGを、未作成文字の代わりに置く
- 未作成判定はコードポイント単位で行い、改行、半角スペース、全角スペースなどの空白と制御文字（タブなど。文字一覧にも追加しない文字）は対象外とする
- 未作成の文字のうち、文字一覧に追加できない文字（絵文字・結合文字など。4.2）は、「対応していない文字」として分けて出し、「入力ページに追加して描く」では追加しない

### 8.3 グリフが0個のとき

「まだ文字がありません。入力ページで文字を作成してください」と表示し、入力ページへのボタンを出す。作成済みの文字があってフォントを作っている途中は「フォントを作っています…」と出す（作成済みかはフォントではなくプロジェクトで数える）。

## 9. 使い方ページ（/）

初めての人が、このページだけで「文字を描く→保存→Wordで使う」までたどり着ける内容にする。文章は静的に書き込んでよい。

**掲載内容**

1. **このアプリでできること**：手書き文字からPCにインストールできるフォント（.ttf / .otf）を作れること。データはブラウザの外に送信されないこと
2. **作り方の手順**：文字列を入力 → 1文字ずつ描いて保存 → プレビューで確認 → フォントをダウンロード（Wordで使うなら.ttf）
3. **きれいに描くコツ**：ガイドの内側いっぱいに描く、お手本を使う、ペンタブレットやiPad＋Apple Pencilがおすすめ、住所・氏名・学校名など履歴書で使う文字から作る
4. **途中保存**：作業はプロジェクトごとにブラウザへ自動で保存され、使い方ページの一覧から開けること。ブラウザの保存はキャッシュ削除で消えるので、「zipで保存」で書き出しておけば「zipを開く」で続きから再開できること
5. **フォントのインストール方法**（フォント名が同じフォントは上書きされるので、別のフォントにするならフォント名を変えること）
   - Windows：.ttfを右クリック →「インストール」。作り直した場合は既存のフォントを削除し、Wordを再起動してから入れ直す
   - macOS：.ttfをダブルクリック → Font Bookで「インストール」
6. **Wordで使うときの注意**
   - フォント一覧から設定したフォント名を選ぶ
   - 作っていない文字は別のフォントで表示されるか、箱印になる
   - 提出前にPDFで保存すると、相手のPCにフォントがなくても手書きの見た目のまま届く。Wordのまま渡す場合は「ファイルにフォントを埋め込む」をONにする。どちらも.ttfを使うこと（.otfはWord文書に埋め込めず、PDF保存で文字が画像になる場合がある）
7. **よくある質問**：文字が箱になる、フォントを更新してもWordに反映されない（再起動が必要）、zipを開けない、など

**ページ内のボタン**

- 「新しくはじめる」：フォント名を入力するダイアログ → 新しいプロジェクトを作って入力ページへ。フォント名の初期値は、このブラウザのほかのプロジェクトと重ならない名前（`MyHandwriting`、なければ `MyHandwriting2`…）にする。同じフォント名（大文字・小文字は区別しない。Windowsと同じ）を選んだら、インストールすると上書きされることを示して確かめる。ヘッダーの「編集」で同じ名前にしようとしたときと、zipを開いて同じ名前のプロジェクトがあるときも知らせる
- 「zipを開いて続きから」：ファイル選択 → 新しいプロジェクトとして読み込み、入力ページへ
- 「このブラウザのプロジェクト」：保存したプロジェクトの一覧（フォント名・作成済みの文字数・更新日時）。開く・削除（確認あり）

## 10. 非機能要件・対象外

### 10.1 非機能要件

| 項目 | 要件 |
| --- | --- |
| 対応ブラウザ | Chrome / Edge / Safari / Firefox の最新版。iPadOS Safari（Apple Pencil）で描画できること |
| プライバシー | 手書きデータを外部に送信しない。アクセス解析タグも入れない |
| オフライン | 初回読み込み後はオフラインでも動くことが望ましい（PWA化は任意）。外部CDNに依存しない |
| 性能 | グリフ保存からプレビュー反映まで300文字時で0.5秒以内、2,000文字時で2秒以内。描画中にカクつかない（60fps目標） |
| 重い処理 | フォントの生成とzipの保存（輪郭・フォント・PNG・圧縮）・読み込みはWeb Workerで実行し、UIを止めない。Workerのファイル名には中身のハッシュを付ける（デプロイの前に開いた画面が新しいWorkerを読み込まないように）。Workerを読み込めなかったときは、ページの再読み込みを案内する。zipの保存・読み込みとフォントのダウンロードは、画面の左下に進み具合と「取り消す」を出す。輪郭のサムネイルは見えているものだけを少しずつ計算する |
| 上限 | 1プロジェクトあたりグリフ5,000個までを想定 |
| アクセシビリティ | ボタンにラベルを付ける（読み上げの名前に、見えている文字をそのまま含める）、キーボードで主要操作ができる（文字一覧の文字の削除を含む）。E2Eで各ページをaxeで確かめる（axeはブラウザの中だけで動き、外部に送信しない） |
| 言語 | UIは日本語のみ |
| 品質 | TypeScript strict、ESLint＋Prettier。`lib/` の主要関数にVitestの単体テスト |

### 10.2 対象外（今回は実装しない）

- アカウント、クラウド保存、フォントの共有
- WOFF/WOFF2の書き出し（fonteditor-coreで対応できるため将来の拡張候補）
- カーニング、合字、縦書き用字形（`vert`）、異体字
- ウェイト違い（太字など）のバリエーション
- 紙に書いた文字の画像取り込み（トレース）
- 制御点を直接動かすベジェ編集
- 絵文字、結合文字

これらを後から追加できるよう、データ形式（`formatVersion`、グリフごとの `widthMode` や `pen`）に余地を残してある。

### 10.3 代替案：サーバーサイド生成

ブラウザ版で受け入れ基準（特にWordへの埋め込みとPDF保存）を満たせない場合に限り、フォント生成をサーバーに移す。初期実装では作らない。

- **構成**：Python＋fontTools（`fontBuilder`）でTTF/OTFを生成。必要に応じてOTSで検証し、ttfautohintでヒンティングを付ける
- **送るデータ**：ベクターJSONとフォント設定のみ。生成後にサーバー側でデータを保持しない
- **影響**：「ブラウザ内で完結」の前提が崩れるため、使い方ページとプライバシーの記述を見直す。ホスティング（Cloud Run等）が必要になる
- **備え**：クライアント側は `lib/font` のインターフェース（`GlyphOutline[]` と `FontSpec` を受け取り、ArrayBufferを返す）を保ち、生成の実装だけを差し替えられるようにしておく

### 10.4 配信

| 先 | 方法 | ルーター |
| --- | --- | --- |
| GitHub Pages | `main` へのpushで `pages.yml` がビルドしてデプロイ | `basePath` は `/MyFontStudio` |
| GitHub Container Registry | `main` へのpushで `publish.yml` がイメージをビルドして `ghcr.io/osawa-koki/myfontstudio`（タグ `main`・`sha-<コミット>`）にプッシュし、Trivyで脆弱性を調べる | ルートで配信 |
| Render | ルートの `Dockerfile`（Node.jsで静的エクスポート → 非rootのNginxで配信。`PORT` で待ち受け）。`render.yaml` のBlueprint | ルートで配信。ないページは `404.html` |

Nginxでは、CSP（`default-src 'self'` を基本とし、外部への通信を禁止）・HSTS・`Cross-Origin-Resource-Policy` などのセキュリティヘッダーを付け、ヘルスチェック用に `/healthz` を返す。Next.jsの静的エクスポートはHTMLにインラインのスクリプトを埋め込むので、ビルド時にそのSHA-256を集めて `script-src` に入れる（`'unsafe-inline'` は使わない）。GitHub PagesはHTTPヘッダーを付けられないので、ビルドしたHTMLの `<head>` の先頭に同じCSPの `<meta http-equiv="Content-Security-Policy">` を入れる（`frame-ancestors` は `<meta>` では効かない）。

## 11. 実装ステップと受け入れ基準

フォント生成という最大の技術リスクを最初に潰し、その後に画面を肉付けする順で進める。各ステップの終わりで動作する状態を保つこと。

### 11.1 実装ステップ

1. **基盤**：Next.jsプロジェクト作成（静的エクスポート）、ルーティング、共通ヘッダー、型定義（`types/project.ts`）、zustandストア
2. **変換と生成の検証**：`lib/glyph` と `lib/font` を実装し、固定のテスト用ストロークから.ttfと.otfを生成。fontTools（`ttx`）でテーブルの値を、OTS（ブラウザと同じフォントの検証器）でフォントとして正しいかを確かめる。WindowsとmacOSでインストールし、Wordで表示できること、.ttfが.docxに埋め込めること、WordのPDF保存で文字がテキストのまま（選択・検索できる状態で）残ることは、実機での手動確認とする（CIでは確かめられない）。満たせない場合は10.3の代替案を相談する
3. **手書きCanvas**：描画、ガイド、お手本、元に戻す/やり直し、筆圧、ペン設定
4. **入力ページ**：文字列取り込み、文字一覧、保存と次への遷移、プリセット追加、ショートカット
5. **適用画面**：FontFace登録、textareaと表示エリア、未作成文字の表示切替えと一覧
6. **zip保存・読込**：書き出し、読み込み、バリデーション、エラー通知、IndexedDB自動保存と復元
7. **使い方ページと仕上げ**：説明文、レスポンシブ、未保存警告、性能確認（300文字・2,000文字のダミーデータ）
